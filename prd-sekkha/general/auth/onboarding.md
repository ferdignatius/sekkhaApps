# PRD: User Onboarding - Sekkha Apps

| Metadata | Detail |
| --- | --- |
| **Document** | Product Requirement Document (PRD) |
| **Feature** | Post-registration onboarding |
| **Domain** | Authentication and Profile |
| **Version** | 2.1.0 |
| **Status** | Approved / Ready for Development |

---

## 1. Purpose

Onboarding introduces newly registered or first-time claiming users to Sekkha, gathers initial profile data, and allows school selection before landing on Home. It is triggered immediately after successful sign-up email OTP verification or during account claim.

Principles:
- **Concise & Non-blocking**: Mobile-friendly, simple, and skippable where stated.
- **Required Fields**: Only `username` and `fullname` (nama lengkap) are mandatory during onboarding.
- **Optional & Skippable**: All other profile fields (`school`, `class_grade`) can be skipped during onboarding and filled/edited later via the User Profile edit page (`/profile` or `/settings`). (`phone` and `birth_date` have been removed from the system for data minimization under UU PDP No. 27/2022.)
- **No Product Tour**: Product tour/walkthrough is completely removed. After completing or skipping optional onboarding steps, user immediately proceeds to Home (`/home`).
- **Self-Registration Claim State**: User registering manually via sign-up with email OTP automatically has `isClaimed = true` upon creation.
- **School Request & Search**: Users search for existing schools by name. If not found, a dedicated button allows requesting a new school (`status: "pending"`). Only active and approved schools appear in the school selection dropdown.

---

## 2. Entry and Exit Rules

1. **Sign-up User Flow**:
   - User verifies email OTP (`/api/auth/register-verify-otp`).
   - Account is created with `role: "member"`, `isClaimed: true` (automatically set to true for self-registration via email sign-up), and `onboardingCompleted: false`.
   - User is redirected to `/onboarding`.
2. **Account Claim User Flow**:
   - User created manually via People pre-provisioning (`isClaimed: false`) logs in with dummy credentials.
   - User changes password and verifies email (claim account completed -> `isClaimed = true`).
   - User is redirected to `/onboarding` if `onboardingCompleted: false`.
3. **Route Guarding**:
   - Any authenticated user with `onboardingCompleted: false` attempting to access protected routes (e.g. `/home`, `/events`, `/profile`) is automatically redirected to `/onboarding`.
   - Once onboarding is completed (or skipped), backend sets `onboardingCompleted: true`.
   - Subsequent logins directly redirect user to `/home` (onboarding never appears again).

## 3. Account & Identity State

### User Model Fields (Schema Reference)

| Field | Type | Constraint | Purpose & Rules |
| --- | --- | --- | --- |
| `id` | `String` | Primary key (`cuid`) | Unique identifier. |
| `userNumber` | `BigInt` / `Int` | Required, unique | Numeric member ID (`yyyymmddnn` - 10 digit integer), auto-generated by system for both manual people & self-registration. |
| `username` | `String` | Required, unique | Auto-generated or confirmed/edited by user during onboarding. |
| `email` | `String?` | Nullable, unique | Verified email address. |
| `emailVerifiedAt` | `DateTime?` | Nullable | Timestamp of email verification. |
| `isClaimed` | `Boolean` | Default `true` for self-registration, `false` for pre-provisioning | Status indicating whether account has been claimed. Automatically `true` for self-registered users. |
| `onboardingCompleted` | `Boolean` | Default `false` | Status indicating onboarding profile setup is finished or skipped. |

### Account Creation & Claim State Matrix

| Creation Method | Initial `isClaimed` | Initial `onboardingCompleted` | Verification Needed | Final State |
| --- | :---: | :---: | --- | --- |
| **Self-Registration (Sign-Up Email OTP)** | **`true` (Automatic)** | `false` | Already verified during sign-up OTP | Enters `/onboarding`, proceeds to `/home` |
| **Pre-Provisioning (Manual by Organizer)** | `false` | `false` | Requires password change + email verification | Becomes `isClaimed: true`, then enters `/onboarding` |

## 4. Onboarding Steps & User Experience

```
[Sign-up Verified / Claim Completed]
                │
                ▼
       ┌─────────────────┐
       │     Step 1:     │ ◄── MANDATORY: Fullname & Username
       │  Profile Basics │
       └────────┬────────┘
                │ Next
                ▼
       ┌─────────────────┐
       │     Step 2:     │ ◄── OPTIONAL: Search & Select Active School,
       │ School / Campus │     or Request New School (Pending) (Can Skip)
       └────────┬────────┘
                │ Finish / Skip
                ▼
          [ /home (Home) ]  (Product Tour REMOVED)
```

### Step 1: Profile Basics (MANDATORY)
* **Required Fields**:
  - **Full Name (`name`)**: Pre-filled from sign-up / manual provisioning, mandatory to verify/fill (minimum 2 characters).
  - **Username (`username`)**: Pre-filled from auto-generated suggestion, unique, mandatory.
* **Actions**:
  - Button: **"Continue"**.
  - User cannot proceed or skip until both `name` and `username` are valid.

### Step 2: School Selection & Class Grade (OPTIONAL - CAN SKIP)
* **Logic Pencarian & Pemilihan Sekolah**:
  1. User mencari nama sekolah pada input search / autocomplete combobox.
  2. Input query memanggil API pencarian sekolah aktif: `GET /api/configure/schools?search=<query>&status=approved&is_active=true`.
  3. **Hanya sekolah yang berstatus `approved` dan `is_active: true` yang muncul di dropdown list.**
  4. **Jika sekolah tidak ditemukan**:
     - Ditampilkan pesan: *"Sekolah tidak ditemukan"*.
     - Muncul tombol: **"Ajukan Sekolah Baru" (Request School)**.
     - Klik tombol membuka modal/dialog ringkas:
       - Nama Sekolah (`name`): Teks wajib.
       - Jenjang (`type`): Pilihan `SMP` | `SMA` | `SMK` | `Universitas` | `Umum` (wajib).
     - Submit request memanggil `POST /api/configure/school-requests`.
     - Data tersimpan di master tabel `schools` dengan `status: "pending"` dan `requested_by = currentUserId`.
     - Ditampilkan notifikasi: *"Permintaan sekolah berhasil diajukan dan sedang menunggu verifikasi pengurus."*
     - User **dapat melanjutkan onboarding tanpa terhambat** (field `school_id` pada profil user tetap kosong/null terlebih dahulu). Setelah pengurus menyetujui, sekolah menjadi aktif dan user dapat memilihnya nanti di halaman edit profil.
* **Class Grade (`class_grade`)**: Opsional (contoh: "10", "11", "12").
* **Actions**:
  - Button: **"Selesai" (Finish)** (menyimpan pilihan dan menyelesaikan onboarding).
  - Button / Link: **"Lewati" (Skip)**.

### No Product Tour
* Setelah Step 3 selesai atau dilewati, sistem langsung memanggil endpoint penyelesaian onboarding dan mengarahkan user ke `/home`.
* Tidak ada walkthrough, spotlight, atau tour modal.

## 5. API Contracts

Semua endpoint menggunakan response envelope standar Sekkha:
```json
{
  "status": "success",
  "code": 200,
  "message": "...",
  "data": {}
}
```

### 5.1. `GET /api/configure/schools`
Mengambil daftar master sekolah yang tersedia untuk dipilih.
- **Akses**: Terautentikasi (`requireAuth`).
- **Query Params**:
  - `search`: string (pencarian nama sekolah).
  - `page`: number (default: `1`).
  - `limit`: number (default `100` umum; dropdown onboarding menggunakan **`5`** item per fetch dengan infinite scroll saat digulir).
  - `paginated`: boolean string (`"true"` untuk mengembalikan metadata `{ items, total, page, limit, total_pages, has_more }` di `data`).
- **Aturan Filter Backend**: Otomatis memfilter `status = 'approved'` AND `is_active = true`. Sekolah berstatus `pending` atau `rejected` tidak boleh ditampilkan di list dropdown.
- **Response 200 OK**:
  ```json
  {
    "status": "success",
    "code": 200,
    "message": "Schools retrieved successfully",
    "data": [
      {
        "id": "sch_12345",
        "name": "SMA Negeri 1 Jakarta",
        "type": "SMA",
        "is_active": true
      }
    ]
  }
  ```

### 5.2. `POST /api/configure/school-requests` (Request Sekolah Baru)
Mengajukan nama sekolah baru oleh user jika tidak ditemukan pada pencarian.
- **Akses**: Terautentikasi (`requireAuth`).
- **Request Body**:
  ```json
  {
    "name": "SMA Buddha Maitreya",
    "type": "SMA"
  }
  ```
- **Behavior**:
  - Membuat record baru pada tabel `School` dengan:
    - `name`: Nama sekolah (trimmed, unik case-insensitive).
    - `type`: Jenjang sekolah.
    - `status`: `pending`.
    - `isActive`: `false` (atau false sampai diapprove).
    - `requestedBy`: `currentUserId`.
  - Jika nama sekolah sudah ada (baik pending maupun approved), mengembalikan `409 Conflict`.
- **Response 201 Created**:
  ```json
  {
    "status": "success",
    "code": 201,
    "message": "Pengajuan sekolah berhasil dikirim dan menunggu persetujuan",
    "data": {
      "id": "sch_new987",
      "name": "SMA Buddha Maitreya",
      "type": "SMA",
      "status": "pending"
    }
  }
  ```

### 5.3. `PATCH /api/users/me` (Update Profil Saat Onboarding)
Memperbarui data profil pengguna secara berkala di setiap step.
- **Akses**: Terautentikasi (`requireAuth`).
- **Step 1 Request (Wajib)**:
  ```json
  {
    "name": "Budi Santoso",
    "username": "budi48291"
  }
  ```
- **Step 2 Request (Opsional)**:
  ```json
  {
    "school_id": "sch_12345",
    "class_grade": "11"
  }
  ```
  *(Catatan: `school_id` yang dikirim harus berstatus `approved` & `is_active: true`. Sekolah pending dari request tidak boleh dijadikan `school_id`).*

### 5.4. `PATCH /api/users/me/onboarding` (Penyelesaian Onboarding)
Menandai bahwa onboarding telah selesai atau di-skip oleh user.
- **Akses**: Terautentikasi (`requireAuth`).
- **Response 200 OK**:
  ```json
  {
    "status": "success",
    "code": 200,
    "message": "Onboarding completed successfully",
    "data": {
      "onboarding_completed": true
    }
  }
  ```

## 6. User Stories

| ID | Sebagai | Saya ingin | Supaya |
| --- | --- | --- | --- |
| **US-ONB-01** | Pengguna yang baru mendaftar / menyelesaikan klaim | Diarahkan otomatis ke alur onboarding ringkas | Saya dapat melengkapi identitas dasar saya sebelum menggunakan aplikasi |
| **US-ONB-02** | Pengguna di Step 1 Onboarding | Memverifikasi dan menyesuaikan nama lengkap serta username unik | Identitas saya tercatat dengan benar dan dapat digunakan untuk login |
| **US-ONB-03** | Pengguna di Step 2 Onboarding | Mencari dan memilih institusi sekolah/universitas yang sudah terverifikasi aktif atau memilih opsi "Skip" | Profil akademik/almamater saya terhubung ke komunitas vihara |
| **US-ONB-04** | Pengguna di Step 2 Onboarding | Mengajukan penambahan sekolah baru jika sekolah saya belum terdaftar di sistem | Pengurus dapat memverifikasi sekolah saya tanpa menghambat saya menyelesaikan onboarding |
| **US-ONB-05** | Pengguna yang selesai onboarding | Langsung masuk ke halaman `/home` tanpa terganggu pop-up tour/walkthrough | Saya bisa langsung melihat jadwal acara kebaktian dan kartu anggota digital saya |
| **US-ONB-06** | Pengguna belum selesai onboarding | Dicegah mengakses rute utama aplikasi (`/home`, `/events`, dll.) dan diarahkan ke `/onboarding` | Sistem memastikan identitas wajib saya terpenuhi sebelum beraktivitas di aplikasi |

## 7. Matrix Kriteria Penerimaan (Acceptance Criteria)

| ID | Skenario Pengujian | Hasil yang Diharapkan |
| --- | --- | --- |
| **AC-ONB-01** | User mendaftar akun baru mandiri via sign-up email OTP | Akun berhasil dibuat dengan `isClaimed = true` dan `onboardingCompleted = false`. User langsung diarahkan ke `/onboarding`. |
| **AC-ONB-02** | User di halaman Step 1 Onboarding mencoba lanjut tanpa `name` atau `username` | Validasi error muncul. Form tidak dapat di-submit dan tidak dapat di-skip. |
| **AC-ONB-03** | User mencari nama sekolah yang sudah terdaftar dan aktif di Step 2 | Nama sekolah muncul di dropdown dan dapat dipilih (`school_id` tersimpan). |
| **AC-ONB-04** | User mencari nama sekolah yang belum terdaftar di Step 2 | Muncul tombol "Request School". User mengisi modal pengajuan. |
| **AC-ONB-05** | User submit pengajuan sekolah baru | Request tersimpan dengan status `pending` dan `isActive: false`. Sekolah tersebut **tidak langsung muncul** di dropdown pemilihan. User dapat menyelesaikan onboarding. |
| **AC-ONB-06** | Organizer meng-approve pengajuan sekolah di panel admin | Status sekolah berubah menjadi `approved` dan `isActive: true`. Sekolah kini muncul di dropdown pemilihan sekolah profil. |
| **AC-ONB-07** | Selesai Step 2 Onboarding (baik isi sekolah maupun skip) | Sistem memanggil `PATCH /api/users/me/onboarding` -> `onboardingCompleted = true` -> langsung redirect ke `/home` **tanpa ada product tour**. |
| **AC-ONB-08** | User yang sudah menyelesaikan onboarding login kembali | Langsung diarahkan ke `/home`. Halaman `/onboarding` tidak pernah muncul lagi. |
| **AC-ONB-09** | User yang melewatkan data opsional membuka halaman Edit Profile | Semua data opsional (`school`, `class_grade`) dapat diisi dan diedit secara manual. |
